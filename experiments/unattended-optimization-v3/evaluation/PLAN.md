# Version 3 independent final evaluation plan

Status: corrective candidate, 2026-10-01 UTC; new implementation review, realistic setup controls, and immutable freeze required. No v3 endpoint assessment has run. This evaluator is owner-controlled and outside participant inputs and write scopes. It is not a development tool.

## Endpoint embargo and assessment identity

All three planned campaigns must have immutable exact-source endpoint seals before candidate assessment runs or any held-out result is released. A normally completed campaign contributes its last promoted artifact, or the unchanged seed if none was promoted. An admitted stopped-state seal retains its explicit incomplete status and reason. A compromised or unsealable artifact is not silently repaired or replaced. No fourth campaign replaces an inconvenient outcome.

The first assessment has a cohort identity bound to those seals, frozen evaluator/configuration, original seed, fixtures, and technical settings. A new output directory or repeated invocation cannot reset that identity. Once final feedback exists, no source repair, reselection, altered threshold, extra research turn, or best-historical-endpoint selection is permitted.

## Prespecified comparisons

Each endpoint is compared directly with a freshly built original seed under canonical compilation and invocation boundaries. The primary transfer portfolio contains the six development workload shapes, sizes, and distribution parameters with independently frozen seeds. The secondary distribution-shift portfolio changes sizes, stream cardinalities, and timestamp distributions. Report these as separate six-family strata, with the exact frozen definitions available in the evidence package.

Each stratum uses thirty complete paired temporal blocks, fifteen pairs in each arm order per family, common calibrated batch counts, and raw sample retention. Family speedup is the exponential of the median paired log reference/candidate ratio. The portfolio is the equal-family geometric aggregate. Joint complete-block bootstrap resampling uses the same frozen implementation as development: 10,000 draws, seed 2026100302, and the interpolated tenth percentile as the nominal one-sided 90% lower bound. Frozen order seeds and the realized schedules are retained. Conditional exchangeability of complete blocks is an assumption; measurement blocks are not independent campaign replicates.

Final evaluation has no performance-selection threshold. Report every valid point estimate, one-sided portfolio bound, family paired ratio, absolute timing, and resource observation, including no gain and regression. Do not multiply development gains or reuse an old absolute baseline time. A source-identical endpoint remains a valid negative outcome; source identity alone is not a measured A/A result.

## Correctness and diagnostics

The evaluator runs exact correctness and technical resource checks for both final strata before timing an endpoint. Named contract probes may overlap development intentionally; random/metamorphic cases use a separate namespace. A confirmed failure in either stratum makes that endpoint invalid rather than yielding a speedup from the other stratum. There is no substitute source after a failed check.

Memcheck covers the configured diagnostic families and input sizes. Report that actual coverage, including any reduced cases and branches not exercised. Passing maximum-size correctness tests does not imply maximum-size instrumented-memory coverage. Passing all configured checks is finite evidence about those inputs, not a proof of the complete contract.

## Shared scheduling and immutable timing attempts

The final evaluator must use the same exclusive scheduler and attested recovery implementation as development. All build, test, profile, memory-check and timing jobs take the execution lease. Routed arbitrary participant shell uses that lane; bounded structured reads and model planning can remain available. The host is not claimed to be dedicated or free of unrelated load.

One benchmark request can contain multiple immutable timing attempts only under PROTOCOL.md §8. An observed competing study-command overlap in otherwise-passing execution, or an owner-attested external preemption with observer/event identity and confirmed cleanup, may invalidate an attempt. Preserve its raw samples, command/cleanup receipts and reason. Requeue a complete comparison with the exact same source, candidate binary, reference binary, fixture identities, configuration, calibration/measurement rules, and review/assessment binding. Verify identities before and after each retained attempt. Do not pool partial invalid samples into the later complete comparison.

The first complete valid attempt is binding regardless of its score. A valid low portfolio score, unfavorable lower bound, family regression, or scored sample below the calibration target never authorizes a retry. Candidate hangs, resource-limit violations, correctness or memory failures, generic infrastructure exceptions, explicit cancellation, broken bindings, and uncertain cleanup do not authorize automatic measurement recovery. No arbitrary retry count or research deadline is introduced. An attempt rejoins the scheduler queue so other admitted work is not starved.

Unknown or nonclean process cleanup quarantines new resource work. A true unresolved integrity, transport, model-routing, or evaluator blocker remains distinguishable from a recoverable timing interruption and leaves a terminal report with unavailable values where necessary. The recovery rule operates inside the original assessment identity; it does not permit a second favorable assessment. A later amended execution, if authorized, must remain separately identified.

## Evidence and new preflight requirements

Freeze the generator, expected-output oracle, evaluator source, technical limits, schedules, estimator, recovery classifier, output schema and source/fixture bindings before the first measured v3 optimizer starts. Keep final data and endpoint results outside measured role inputs. Instructions and host-owned paths do not alone establish adversarial read isolation; verify and report the actual sandbox/read boundaries.

The current implementation must pass new setup evidence for the all-endpoint embargo, admitted incomplete seals, source/binary/fixture binding, wrong-result/resource rejection, actual diagnostic coverage, paired A/A calibration, score-blind recovery through the final path, first-assessment identity, and terminal-blocker handling. Use labeled setup artifacts and preserve failures. Prior-version controls and a direct backend A/A run cannot establish that the new final orchestration works.

Archive every valid, invalid, failed, and interrupted operation with immutable IDs and links to its measurement series. Keep assessment elapsed time, queue/cleanup/recovery overhead, native resource use and available usage distinct from campaign source-seal time. The final report is an observation of this fixed cohort on one synthetic task; it cannot establish general workflow efficacy or causal effects of the scheduler.
